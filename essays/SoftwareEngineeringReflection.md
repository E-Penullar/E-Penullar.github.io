I think I've learned quite a bit about Software Engineering during this Summer. Much more than I anticipated at least. Originally, I had a vague understanding as to what Software Engineering is — something to do with programming for a specific task or purpose, I suppose — but throughout this course I feel like a have less vague and more somewhat-explicit understanding. Truly, I've had a slight interest in programming web applications or at the very least about how websites worked and operated. And now that interest has transformed into a fond appreciation for the work programmers and developers do, especially now that I've experienced said work first-hand.

<hr>

## Working Hard or Hardly Working?

Knowing what I know now, I've got a real appreciation for people who make their code open source, or open and available to the public. Not only as a source of open collaboration with either strangers or — in regards to this class — fellow students, but also because I enjoy having the documentation to a specific gimmick or feature that I like. Which is also why I appreciate UI (User Interface) Frameworks; during this course, when we were working on assignments that focuses on UI Frameworks, I really enjoyed the publicly available documentation of web page aspects that I enjoy. For example, for the [Your Choice Assignment](https://courses.ics.hawaii.edu/ics314summer26/morea/ui-frameworks/experience-yourchoice-bootstrap.html), I chose to recreate the [UH Manoa Homepage](https://manoa.hawaii.edu/) to the best of my ability using [Bootstrap 5](https://getbootstrap.com/docs/5.0/getting-started/introduction/) — a very popular framework. The original site utilized an image carousel, which is a design element that cycles through multiple pictures in one spot — it is a very fascinating and fun interactive feature, and I was very glad that there was code for such a thing within the Bootstrap documentation. Of all the feature within my recreation, my favorite would definitely be the image carousel. I think if I were to ever try that assignment again for a different site, I'd like to try something like items that react to when the cursor hovers above it, or user customization of a site's style (colors, text size or font, etc.) — something just as interesting. There'd probably be open source code somewhere for that kind of thing, hopefully.

Although some concepts still elude me at times, like Design Patterns. I think understand the potential benefits of having reusable blueprints for solving common software design problems, but I'm not sure I'd be able to recognize them easily with the work of mine or others, at least not without a bit of help and pointers. Maybe I'd need to work on programming a bit more outside of this course — working on personal projects might knock a few gears into action. That and understanding how Functional Programming works — don't get me wrong, I think I've learned quite a bit since starting this course and working in TypeScript / JavaScript, but there's always room for improvement, and developing with predictable, mathematical functions can be a bit difficult if you habitually code step-by-step.

And speaking of Typescript and Javascript, learning a new coding language is kinda exciting. It's a bit of a different experience compared to learning Python, Java, C, and C++, but I can't deny its merits. Though learning the proper Coding Standards was a bit difficult; everything's got different guidelines and formatting styles, so it took a while getting used to the difference in using 'class' vs. 'classname' for element attributes. But learning to code a bit better is always a plus — although, I found learning about HTML and CSS to be more interesting, both in terms of syntax and overall vibe.

## Managing Upper Management (a.k.a. my Brain)

I think for more extensive or larger projects, like the Final Project, I'd like to think I've gotten better at managing a lot of tasks in a certain period of time. Which relates to concepts like Configuration Management — the process of maintaining consistent performance and functionality of code, and Agile Project Management — breaking up large projects into short tasks / iterations, the latter more so than the former. Similarly to the [BrowserHistory Assignments](https://courses.ics.hawaii.edu/ics314summer26/modules/ui-basics/) or the [Digits Assignments](https://courses.ics.hawaii.edu/ics314summer26/modules/nextjs-3/), where an overall lesson on webpage user interface development was split into multiple parts. I found this approach to be very insightful; while it would've been okay to just lump each part into a single assignment, I see the value in taking in everything one step at a time. Although, I feel like the assignment on the [5 Navbars](https://courses.ics.hawaii.edu/ics314summer26/morea/ui-frameworks/experience-bootstrap-navbars.html) was a weird experience, especially when there are other aspects that could've been more expanded upon, like the overall experience of developing a homepage or linking items to other pages like some sort of digital pick-your-own-adventure. And as for Configuration Management, I was either doing this subconsciously or consciously, whether I was testing and refreshing pages to ensure my code functioned how I wanted it to, or I ran ESLint to identify errors I couldn't see at first.

## This is my Office, and my Laboratory (... It's More of an Allegory)

I think of all the development environments or code editors I've worked with, I really enjoyed using VSCode a lot. Eclipse IDE was fine for what it was, but I find it to be a bit too old fashioned compared to VSCode, and Replit is too confusing and AI-reliant for me to properly enjoy. With VSCode, I feel more free to work however I'd like, and the extensions are a nice breath of fresh air to make coding a bit more fun. One such extension I've found is a [Color Highlighter](https://marketplace.visualstudio.com/items?itemName=naumovs.color-highlight): it just highlights a color in your code, with their color. It's not that exciting, but pretty cool.
